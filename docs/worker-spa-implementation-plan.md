# Worker 托管访谈 SPA 与题包闭环实施方案

本文记录已授权的云端实施范围和仍待确认的产品选项。开发目标为 nilpwoer/corch-dsh 的独立分支；业务代码通过本次验收后获准推送开发分支；PR、合并和公网部署没有获得授权。本文按用户指定以中文保存在此路径，未建立英文对照或翻译配对记录。

## 1. 结论与实施前提

完整需求属于中等改动：静态母版托管和按 ID 读取 JSON 较小，主要工作在 worker 的多题包适配、真实会话、回答幂等、AI 追问、恢复和报告。优先把运行逻辑放在 worker，DSH 只补必要的类型、解析、导出和访谈策略设置，不重写母版外观，也不替换已有主持人审核与发布操作。没有经验证的工时估算。

实施基线已从 fork 的 codex/go-teaching-worker 取得，提交为 2e2c1433f27a632eb5506d96e998c06403d8f72e。不能把 DSH 内部的 workflow-worker-thread 或 code-runtime-worker-thread 当作访谈 HTTP worker，也不能仅凭本文完成现有 worker 的最终改动评估。

### 1.2 已确认需求

- worker 根路由托管项目现有默认访谈 SPA 母版，兼容现有母版文件路径。
- 主持人按原 DSH 工作流程生成、审核、导出题包；worker 启动配置决定题包目录，支持人工文件上传和 Web 管理端上传。Web 管理端管理题包与报告，账号从现有 MySQL 读取，初始化用户名为 admin，不强制首次改密；不硬编码、记录或传播真实初始密码，不扩展复杂 RBAC。
- 必须接通真实答题、AI 追问及报告；静态展示、浏览器暂存和假提交不能算完整闭环。
- AI 依据访谈目标、专家背景、主问题和回答历史决定是否追问，不强制 required_slots，不把槽位缺失当作必需追问条件。
- followUp 保留为可选提示；追问次数由题包设置，不要求管理员在服务器中为每个包配置次数。
- 尽量仅调整 worker；DSH 限于必要的类型、解析、导出和设置，母版只做真实接入必需的最小改动。

## 2. 现有机制与差异

### 2.1 云端 main 中的母版与 DSH

母版源文件为 [apps/web/public/practice-expert-interview-spa.html](../apps/web/public/practice-expert-interview-spa.html)，是一份内联 CSS/JS 的静态 HTML。它从查询参数取得 fieldnoteId，无 ID 时显示 FN-DRAFT 演示题；有 ID 时请求同源 /interviews/<ID>.json，失败时仍会尝试同源 localStorage 中的该 ID 缓存，缓存不可用才显示题包不可用。跨域部署不能依赖 DSH 浏览器 localStorage 将题包转交给 worker。

母版只有回答的本地保存和提交状态切换；最终点击不构成服务端接收或报告完成。它没有题包目录扫描、题包列表、多设备恢复和正式追问 API。已有语音输入、题目导航、选项、暂存和进度需要在 worker 接入后保留；语音能力仍取决于浏览器支持。

[根目录同名文件](../practice-expert-interview-spa.html) 是跳转包装，不是母版源文件。按 [apps/web/package.json](../apps/web/package.json) 和 [Vite 配置](../apps/web/vite.config.ts)，母版预期随 public 静态文件复制到 dist/practice-expert-interview-spa.html。云端基线没有已跟踪的 dist，本次没有构建验证；实施时须明确部署采用版本固定的源 HTML 还是已构建产物，不能假设 checkout 自带 dist。

[InterviewWorkbench.tsx](../packages/client/ui-polus-teaching-reform/src/client/InterviewWorkbench.tsx) 的 publishSpa 保存载荷到 localStorage，并打开固定公网域名下的 /practice-expert-interview-spa.html?fieldnoteId=<公开ID>，不导出文件、不上传服务器、不调用安全发布 API。SpaTab 工作台预览直接使用 React props，不能把预览成功解释为公网发布成功。公开 ID 会把中文后缀转换为拼音，JSON 内的原始 fieldnoteId 保留，文件映射必须兼容这一差异。

现有载荷包含 fieldnoteId、profile、questions、questionPackMeta、invitation 和 publishedAt；questionPackMeta 包括 packId、version、generatedAt、sourceSessionId、checksum 及可能的 globalReferences。followUp 为可选字符串，sourceRefs 记录问题设计来源，不是受访者回答证据。DSH 当前解析不会完整保留 required_slots，结构化 trigger/next 会被兼容解析压成文本，不能依赖这些字段驱动新的运行状态机。

DSH 的 [frontend-static](../packages/host/frontend-static/src/index.ts) 与 [webserver](../packages/host/webserver/src/index.ts) 是另一个主机实现：命名精确路由先匹配，其次最长前缀，最后单一 fallback；静态服务仅根路径和指定 index 渲染入口，缺文件返回 404。它不是访谈 worker 的服务机制，不应为接入访谈而修改其全局 fallback。

### 2.2 本地评估提供的 worker 事实

以下机制已在取得的 worker 基线复核，路径位于独立 worker/ 模块；它们不在原 main 基线中。

- worker/internal/config/config.go：preview 使用 assets_dir 和单个 pack_file，严格解析 YAML；preview 限制回环 IP，且只在 api/both 模式启用。
- worker/internal/service/preview.go：mountPreview 在启动时读一次单包，根路径重定向母版并带 worker=1，未提供目录索引。
- apps/web/public/practice-expert-worker.js：请求 /browser/session 时不传题包 ID，并重绘 #app；评估发现没有完整保留母版语音入口。
- 本地母版通过 worker=1 切入桥接模式；main 母版没有该分支，因此不能直接拿 main 母版注入桥接脚本并假设普通初始化会停止。
- worker 的严格 preview DTO 与 DSH 导出字段存在冲突：多余字段会被拒绝，并要求槽位；桥接只投影 id/question/required_slots，没有使用 followUp/sourceRefs。
- worker engine 通过服务端 max_followups 和 analyze/compose YAML 控制运行；新需求必须把业务次数迁到题包，并把判断改为无强制槽位的 AI 决策。

### 2.3 改动分级

| 工作 | 判断 | 依据 |
| --- | --- | --- |
| 已有 HTTP worker 返回母版，按 ID 提供 JSON | 小 | 母版自包含且读取路径明确，但需核实真实 worker 路由 |
| 多题包目录索引、DTO 兼容、安全读取、人工发布流程 | 小到中 | 涉及外部文件输入、ID 映射、版本和发布原子性 |
| 会话绑定、真实回答、AI 追问、恢复与报告 | 中 | 需要跨请求状态和失败恢复，且现有槽位及单包假设均需调整 |
| 重写 DSH 工作台、重做 SPA、引入复杂账号平台 | 大且不在本方案内 | 保留流程与母版，仅增加已授权的最小管理登录、题包上传及报告界面 |

## 3. Worker 配置、目录与题包接入

### 3.1 独立 portal 配置

新增独立 portal 配置段，不复用 preview 的含义。建议字段为 enabled、assets_dir、packs_dir；HTTP 监听、模型连接及管理员配置复用现有对应配置。字段名均待源码复核。preview 的回环 IP 与 api/both 限制保持，不以放宽 preview 作为公网服务方案。

portal 启动时解析配置目录的绝对路径，验证存在、类型和权限；未配置、目录不可读或资产缺失应清楚报错，不能静默切换到演示题或任意工作目录。若允许 portal 监听非回环地址，必须通过独立显式配置并完成会话鉴权，不隐含改变 preview 的访问范围。

### 3.2 目录发现与人工上传

推荐目录以一个正式 JSON 对应一个已发布包版本，worker 读取 JSON 内的包身份与版本形成索引；文件名只是映射信息，不作为唯一业务身份。目录布局、是否允许子目录以及相同公开 ID 的多版本选择规则在实施前固定，不自动把字典序最后的文件当作有效发布。

人工操作顺序为：DSH 导出题包，文件工具上传到同一文件系统中的暂存文件或暂存目录，完成后校验，再原子重命名为正式文件。worker 忽略暂存命名、非允许扩展名、非法 JSON 和不完整包，不向新会话展示上传中的半成品。原子替换必须在目标文件系统内进行；若工具不支持，先上传暂存目录，再在服务器完成校验与重命名，而非边覆盖边对外读取。

最小实现可以在列举或打开题包时按需扫描，暂不引入复杂文件监听；后续按实际目录规模决定缓存与失效策略。扫描失败记录可定位错误，读取已有有效版本失败则返回明确错误，不将坏文件伪装成空包。索引校验与实际读取必须校验同一内容或重新比较哈希，避免文件扫描后被替换导致版本错配。

目录发现属于 worker；浏览器无法直接扫描服务器目录。若确认使用公开列表，worker 提供经授权的最小题包摘要，前端增加列表入口。若确认专属链接模式，则 worker 内部发现目录，SPA 通过 ID 加载指定包，不需要公开列表。

### 3.3 路径与资源保护

只接受符合已定义格式的公开 ID 或由索引产生的内部包键，拒绝斜杠、反斜杠、空字节、点段和非法编码；解码次数必须一致。文件读取验证规范化路径和符号链接目标都在配置目录内，拒绝越界符号链接、目录请求和任意文件名输入，不开放服务器目录浏览。

JSON 响应明确返回 application/json，缺包、缺版本和资源缺失返回相应错误，不能落入母版 HTML。只提供经过解析和授权的题包视图，不把上传目录挂成任意静态根目录。当前已核实包格式没有独立附件清单；若实际导出包含附件，先定义版本绑定的资源清单和安全路径，再按清单提供 /packs/<包键>/assets/<资源键> 等受控读取草案，不能把专家资料目录整体公开。

### 3.4 发布包 DTO 与兼容

发布包与 engine 输入分开定义：前者承接 DSH 的信息、版本及策略，后者由 worker 显式转换为运行数据。保持现有顶层字段和可选 followUp/sourceRefs，修复严格 preview DTO 把合法 DSH 字段拒绝的问题；不要直接对公开包使用旧槽位 DTO，也不要靠无条件忽略所有未知字段掩盖拼写错误。

建议引入 schemaVersion 和 interviewPolicy 等发布字段，其中追问策略明确记录范围和次数。准确字段名、版本号、允许范围及单题覆盖仍待确认。DSH 类型、结构化解析和文件导出需完整保留已确认策略；worker 验证次数是合法整数、策略范围已支持，并在会话创建时固化。不得用服务器逐包配置替代该字段。

兼容读取现有无 schemaVersion 的载荷，采用显式 legacy 解析分支和错误信息；legacy 包没有追问策略时，不能静默套用服务器默认次数。建议要求主持人重新导出或在导出步骤补齐确认后的策略。若旧包含 required_slots，可在 legacy 兼容层保留为旧数据，但新的 AI 判断不强制它，也不从缺失槽位推导必需追问。

以完整发布包内容的稳定表示计算内容哈希，并记录哈希算法与规范化方法。现有 questionPackMeta.checksum 只反映问题内容，不能替代包含专家背景与策略的包版本哈希。worker 检查题目 ID 唯一、问题文本、字段类型、身份映射、策略及大小限制；具体大小限制待确认，不以校验失败时删除字段的方式“修复”输入。

导出包可包含主持人侧 invitation 信息；worker 对外题包视图不能下发 invitation.code 或任何模型凭据。导入后按已确认认证方案处理口令，不把完整导出 JSON 原样作为公网 /interviews/<ID>.json 响应。

## 4. 路由与母版接入

### 4.1 路由草案

| 方法与路径 | 建议职责 | 授权与错误 |
| --- | --- | --- |
| GET / | 返回现有母版；无 ID 时的列表或提示待用户决定 | 不默认选择最新包，不把真实服务缺包切成示例 |
| GET /practice-expert-interview-spa.html | 兼容 DSH 现有链接，使用相同母版 | 保留查询参数 |
| GET /practice-expert-worker.js | worker 自有桥接资产，具体文件名复核现有实现 | 不嵌入密钥和口令 |
| GET /api/portal/packs | 可选的题包摘要列表 | 是否公开及摘要字段待确认 |
| POST /api/portal/sessions | 按包 ID、版本和认证信息创建或恢复会话 | 服务端认证；不再隐式绑定单个 pack_file |
| GET /api/portal/sessions/<会话ID> | 返回已授权会话、题目及回答状态 | 校验身份与会话访问权 |
| POST /api/portal/sessions/<会话ID>/answers | 保存回答并推进 AI 分析任务 | 幂等键、题目及版本校验 |
| POST /api/portal/sessions/<会话ID>/complete | 确认最终提交并申请生成报告 | 不以点击成功冒充报告完成 |
| GET /api/portal/sessions/<会话ID>/report | 返回报告状态或获授权的报告 | 报告受众待确认，默认实现不得扩大公开范围 |
| GET /interviews/<公开ID>.json | 兼容读取经授权的题包视图 | 不含口令；认证前是否允许读题待确认 |

这些路径不是已实现 API。取得 worker 后先核对 /browser/session 及已有路由，优先兼容并扩展其能力；若新增 /api/portal 命名空间，明确旧客户端兼容范围，不盲目重复两个状态系统。

命名 API 和题包资源优先匹配，静态资源其次，根页面最后。不存在的 API、JSON 和资源必须返回 404 或明确业务错误，不允许全路径 SPA fallback 把失败变成 200 HTML。当前母版无 History 路由，不需要通用 fallback；未来增加页面路径时单独声明允许回退的页面范围。GET/HEAD 与变更方法分开处理，旧根路由若被占用，先确认迁移策略。

### 4.2 最小桥接与保留母版

worker 提供版本固定的原母版和自有桥接脚本，尽量使用已有 worker=1 入口启动 worker 模式。桥接负责真实会话、加载、回答保存、追问状态和报告状态；母版负责既有外观和交互。不要照搬当前桥接整块重绘 #app 而丢失语音、导航或选项。

实施优先检查已取得版本是否有稳定的 worker 初始化入口。存在入口时扩展该入口，并复用母版的渲染和事件机制；不存在入口时，仅增加启动分支、数据适配或必要事件接口。由 worker 动态注入脚本也是可评估方式，但必须证明普通 localStorage 初始化不会同时运行。不能宣称绝对零母版改动，也不引入另一份长期分叉的母版。

桥接必须从 URL 或已选题包取得明确包 ID，再创建会话；不能沿用“不传 ID、服务器只有一个包”的假设。worker 模式禁用题包 localStorage fallback 与演示题兜底；浏览器本地回答缓存如保留，需以会话和版本隔离，且服务端保存成功才展示已保存。缺包、认证失败、网络错误和模型处理中都有明确状态。

保留母版语音入口、单选与多选、文本、上一题和跳转、进度、暂存、错误与重试；对真实追问和报告只增加必要状态呈现。每项需通过真实页面验收，不能仅比较截图或只测桥接返回值。

现有 DSH 固定域名若继续指向 worker，可保持链接不变；若部署域名改变，必要时只将公网基础地址改成配置。不要为使用根路由强行删除旧文件入口或重写发布按钮。完整的邀请验证接入可能需要最小调整初始化顺序，因为普通母版会先取包、再按公开包中的 code 客户端验证；worker 模式必须走服务端认证流程并避免口令下发。

## 5. 真实会话、回答和恢复

创建会话时绑定公开 ID、packId、版本、完整包哈希和生效追问策略，并保存该版本快照或能够稳定取得该不可变版本的引用。后续人工替换目录文件只影响新会话，已有会话不能悄悄切换问题、专家背景、次数或报告依据。重复 ID/版本但哈希不同应明确拒绝或作为新修订处理，规则待确认。

建议服务端记录会话状态、主问题 ID、追问 ID 与轮次、回答记录、AI 决策、模型执行状态及报告状态。持久化实现和恢复方式须经确认后选择；不能把内存状态或浏览器 localStorage 描述为已批准的长期方案。

每次回答携带会话、当前包版本、问题或追问 ID、客户端幂等键和内容。服务端校验访问权和状态，成功记录回答后再启动分析；相同幂等键及相同内容返回原结果，相同键不同内容返回冲突。防止双击、网络重试和并发标签页制造重复回答、重复追问或超过次数。

建议记录回答修订，明确一次 AI 判断依据哪一版回答。分析期间若允许编辑或跳题，需要取消、废弃或标注旧判断并防止迟到结果覆盖新状态；是否允许分析中编辑及单题跳过仍需结合母版交互与用户确认。最终提交只有在服务端确认接收后显示成功，报告生成与提交成功分别展示。

建议通过会话状态读取恢复页面，并在重启后继续识别已保存回答、追问次数和报告任务；跨设备恢复必须通过服务端认证，不能只凭公开 ID。模型失败、超时或解析错误不得丢弃已保存回答、伪造“足够”结论或自动发出虚构追问；保留可重试状态，失败重试不能重复消耗业务追问次数。

## 6. AI 判断与题包追问次数

### 6.1 判断依据与模型输出

每次分析提供访谈目标、专家背景、当前主问题、当前问题下的主回答及追问回答、必要的全场已答摘要，以及剩余业务追问次数。访谈目标的正式字段需核对现有包；若只有背景而无目标，DSH 仅增加必要保留与导出字段，不凭空声称 profile 已含全部目标。

followUp 作为可选提示输入，sourceRefs 作为问题设计依据输入；两者不能替代真实回答证据。题包文本、followUp、专家回答和上传内容均作为数据，不提升成系统指令，不能要求模型忽略安全规则、泄露密钥或改变次数上限。

建议结构化决策包含 action（继续追问或进入下一主问题）、reason、回答证据引用、可选追问文本和仍不明确的事项，准确字段在实施时固定。追问应针对回答中的含糊、矛盾、重要事实或目标相关缺口；也允许模型判断不必追问。拒绝“只因 required_slots 没填齐而一直追问”的行为。

worker 验证模型输出结构、action、追问文本和证据引用是否对应真实回答；模型输出不能自行修改包策略、会话身份或绕过服务端次数限制。若没有合法证据，标记缺口或错误，不把问题设计 sourceRefs 当作受访者已经陈述的事实。

### 6.2 次数控制

题包决定业务追问次数，worker 在创建会话时固化并执行。范围是每主问题还是整场必须先确认；本方案推荐每题但尚未批准，不能直接写死 per_question。0 禁止生成追加问题，仍可分析回答并在报告注明未澄清事项。

次数在一条追问实际提交为可见问题时计算一次，模型重试、重复请求和失败响应不额外计算。到达次数上限后进入下一步，并保留未澄清事项，不要求专家满足槽位才能继续。服务端可以有全局资源保护限制，但与业务次数分开：超出资源能力时报明确错误，不能静默截断题包要求或将 global max_followups 当逐包规则。

需要调整已评估 worker 的 analyze/compose 输入与输出、engine 判断和计数位置；确切 YAML 文件及符号要在取得源码后定位。不得在代码没有导入题包策略时仅修改提示词并声称次数已接通。

## 7. 报告、证据与访问控制

完成报告以会话固定的题包版本和实际回答记录为输入，包含访谈目标、专家背景、回答摘要、明确引用的主回答与追问证据、未澄清事项及模型推断标记。报告记录模型执行版本和生成状态，重复申请不生成重复业务报告；重新生成或修订需保留可追溯版本。

报告不能把模型补写的案例、问题设计参考资料或未作答题目当成专家证据。证据引用对应稳定的回答 ID 与修订号；汇总和原文分开，原文缺失时清楚标记。页面轮询、SSE 或其他状态获取方式优先复用现有 worker，具体实现后再定，不为本需求新建复杂队列平台。

认证在 worker 服务端执行；若沿用邀请口令，导入后妥善保护其验证材料，对外不下发明文 code。会话凭据与题包 ID 分离，创建、恢复、回答和报告均校验访问权限；管理员与受访者权限分开。凭据寿命、撤销、暴力尝试限制、Cookie 或令牌方式需随已确认认证策略设计，不沿用浏览器 72 小时本地标记作为权威鉴权。

模型凭据只由 worker 获取和使用，不进入母版、公开配置或题包响应。面向网络部署时处理 TLS、来源及请求伪造防护、错误脱敏和最小摘要输出；具体部署操作不在本文授权内。报告可见对象、回答留存和删除规则须确认，不能通过公开题包列表泄露身份或完整回答。

4. 接通 AI 追问：以目标、背景和回答历史驱动结构化判断，使用题包次数；验收无追问、必要追问、0 次、次数到顶、模型失败重试及并发去重。

### 8.3 测试层次与通过标准

自动化测试使用确定性的模型 mock 验证状态、协议、失败路径和次数；它不能证明真实模型判断质量。真实模型验收另行使用经授权的模型配置和测试资料，记录判断依据、实际追问及报告证据。不得输出模型凭据，未执行的测试不得写为已通过。

- 配置与目录：preview 限制不变；portal 缺配置清楚失败；临时文件、坏 JSON、重复版本、符号链接越界和编码穿越都被处理；目录变动不导致跨包读取。
- DTO 与导出：DSH 实际导出可被 worker 接收，followUp/sourceRefs 保留；策略正确往返，legacy 行为明确，未知策略或不合法次数拒绝；公网视图不含口令。
- HTTP 与页面：根路径和旧链接使用母版；API/JSON 缺失不回退 HTML；工作台预览与公网结果分开；语音、选择、文本、跳转及暂存实际可用。
- 会话与回答：会话绑定 ID/版本/哈希；重复提交只产生一条逻辑回答，重复 AI 结果不产生多条追问；目录包替换不更换已开始会话；认证边界不可绕过。
- AI 判断：足够回答可以直接继续，含糊回答可有针对性追问；不依赖 required_slots；次数来自包；模型错误不会丢答案或虚报成功，提示注入文本不改变系统权限和次数。
- 报告与恢复：报告证据引用真实回答版本，推断和缺口明确；报告等待/失败与成功区分；受众权限符合确认结果，持久化和恢复按已批准实现验证。

业务实现后的检查按实际改动选择 worker 的 Go 测试、真实 HTTP/页面集成、DSH 导出测试、必要 GUI 和模型验收；先确认仓库实际命令，本文不提供未经核实的 worker 测试命令。实现验证使用隔离 MySQL 和可控模型；实际运行结果另见开发交付记录。真实模型、生产部署和真实凭据初始化不包含在自动化验证中。

## 10. 明确可配置的实施协议

portal 与 preview 分开，preview 的回环限制保持。管理端为 /admin/，账号与会话使用 MySQL 的 tw_accounts 和 tw_admin_sessions；受访者不需要注册。数据库结构显式从版本 1 升级到版本 2，初始化 admin 只接受 admin_password_hash，既有数据库密码不被配置覆盖。

hash-password --output <新建私有文件> 只从 stdin 读取输入，用带随机盐的 PBKDF2-HMAC-SHA256 强哈希写入新文件，不打印密码或哈希、不覆盖旧文件。实际密码输入与持久设置需单独授权；测试使用合成值。没有明文默认密码或强制首次改密流程。

participants_enabled 默认关闭；开启前必须显式选择 entry_mode（link/list）、invitation_mode（code/none）和 participant_reports（allow/deny）。这些支持选项不是替用户决定默认策略。题包 interviewPolicy 明确记录 scope（per_question/interview）与 maxFollowups，未配置不能创建访谈会话；0 禁止追加问题，服务器不为每包补默认次数。

上传先校验再通过同目录原子操作发布，相同键不同内容拒绝覆盖。会话保存题包副本、版本、完整哈希和策略；移除目录题包不改变已绑定会话。管理端和受访者 Cookie 分开，报告按显式配置控制受访者输出；管理端可读取报告任务及证据并下载 JSON。报告管理当前列举最近 200 个任务。

DSH 单击“发布并打开 SPA”后通过既有 Worker 登录会话上传，登录缺失时正常登录后自动继续，无需 Worker 再次确认；只有匹配回执才标记发布。按钮附近显示状态及错误，缺少地址时提供设置入口；旧 Worker 在题包传输前提示更新。DSH 的问题包操作栏保留发布、JSON 下载和新版本操作，不提供访谈目标或追问策略表单；SPA 预览仅保留专家访谈口令和分享链接。新题包和新版本不携带初始追问策略，由 Worker 管理端显式配置。既有题包同版本重试保留旧目标和旧策略，避免改变已发布内容。Worker 模式保留母版样式、文本与选项、导航、语音入口、暂存、追问和回看交互。

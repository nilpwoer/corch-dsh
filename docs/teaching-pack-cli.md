# Teaching-pack CLI

English | [中文](teaching-pack-cli.zh.md)

The repository command `pnpm teaching-pack --host http://127.0.0.1:3082/ --request /absolute/request.json --output /absolute/new-output-directory` generates through an existing DSH Web Host. `node --import tsx/esm scripts/teaching-pack.ts` runs the same source entry without package-manager startup. The Host must already serve a DeepSeek default model and manage its own credentials; the CLI never reads credential files, changes model defaults, or attaches to an existing conversation.

The request contains `fieldnoteId` (a unique URL-safe test identifier), `goal`, `questionCount` (3–100), explicit `profile` fields, nonempty `sources` with `id/title/markdown/version`, and `interviewPolicy` with `scope/maxFollowups`. Inputs belong to the actual task: label synthetic roles, provide only authorized material, and do not put keys or passwords in requests. Browser-only custom prompts and reference pools are not read; the CLI explicitly uses the repository methodology template and supplied references. References describe question-design sources, not participant answers.

The CLI creates a new session, verifies its current DeepSeek route, submits the prompt, and waits for that session's completed turn. It shares parsing, numbering, source validation, provenance metadata and publication creation with the workbench. Invalid model output fails instead of substituting questions. The exclusive output directory retains the request, rendered prompt, actual session identifier, original model output, non-secret evidence, and `publication.json`. Publication files contain invitation codes: keep the directory private and transfer them through the authorized SSH connection. Standard output omits codes and their whole-publication digest. `--timeout-ms` bounds the generation wait and cancels only the new session on expiry.

On the Worker host, `teaching-worker import-pack --file /private/publication.json --packs-dir /authorized/packs --key TEST-unique-v1 --max-bytes 1048576 --require-invitation --dry-run` validates without writing. Use the deployment's actual publication size limit. Running without `--dry-run` uses the same parser and atomic immutable publication operation as administrator upload. Repeating identical content is idempotent; different content at the same key fails. The command requires existing OS directory permissions, loads no service configuration, connects to no database and starts no listener. A separately built tool can import without replacing or restarting the running service.

Verify the resulting key through the configured participant entry and anonymous-access protections. CLI generation and local import do not constitute browser UI, microphone, participant-answer, follow-up-model or report-pipeline acceptance.

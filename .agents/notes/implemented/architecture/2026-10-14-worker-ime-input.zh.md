# Agent Note: 保留访谈输入法组合状态

Status: implemented

[English](2026-10-14-worker-ime-input.md) | 中文

## 问题

Worker 桥接脚本在主回答每次输入时替换整个应用标记，在输入法组合过程中销毁已聚焦的 textarea。给替代节点恢复选区不能保留浏览器的输入法组合会话。补充回答草稿还会保存尚未确认的预编辑文字。

## 决策

编辑主回答时保留 textarea，只更新确认状态、进度和已失效的分析元素。两个回答框监听组合输入事件，到 compositionend 才提交草稿值，并忽略值未变化的末尾重复 input。已确认的输入仍同步暂存。组合过程中请求的渲染延后到最终 input 完成；其他渲染在适用时恢复文本框焦点、选区和滚动位置。

隔离浏览器回归加载实际 SPA 和桥接脚本，配合合成会话响应。它覆盖组合事件、组合期间保存和渲染、插入光标、普通键入、粘贴输入事件、单多选、刷新恢复、补充草稿和失效分析清理，不发起模型请求。

## 考虑过的替代方案

**每次输入渲染后恢复焦点：**这会在组合结束前替换输入法持有的节点，同样复现问题。

**保存每个预编辑输入，或对全部保存做防抖：**预编辑内容尚未确认，延迟保存已确认内容又增加刷新时的数据丢失窗口。确认后的输入立即保存，不重建回答框。

**为静态修复替换生产 Worker：**portal 在启动时缓存桥接脚本字节。仅针对单个脚本的 Nginx 静态覆盖可以不重启 Worker 而提供已测试脚本；部署必须附带撤销覆盖流程，防止遮蔽未来版本资源。

## 影响

浏览器保留组合输入节点，草稿格式不变。无头事件模拟验证 DOM 行为，不等同于 Windows 原生输入法集成验收。线上补丁要求备份资源和配置、限定单脚本精确路由、保留 MIME 和 no-store 响应头、reload 前验证 Nginx，以及核对公网字节。[运维流程](../../../../docs/worker-ime-hotfix.zh.md) 记录回退与正式升级时的清理方式。

# Agent Note: 可追溯访谈输入与有界文字追问

Status: implemented

[English](2026-10-16-traceable-interview-inputs.md) | 中文

## 问题

文献标题和编辑摘要不能证明哪些原文进入了问题生成。缺少策略会阻断已经授权的发布；为所有选择题提供文本框，又会让非文字回答进入模型追问。管理员需要看到已保存设置，同时不能暗中改变进行中的访谈。

## 决策

内置主持人提供的 14 份 Markdown 正文、原始路径和 SHA-256，保留 12 个稳定来源 ID，新增两份不指定等级。用户已有非空正文和保存的选择优先于种子，缺少正文明确报错。全文检索与预览使用正文；生成接收有预算限制的原文摘录及原始 Markdown 行列定位，发布元数据保留摘录与摘要。不推断 OCR 书目信息或纸书页码。

客户端保存的生成模板渲染后通过 `session.prompt` 作为用户消息提交，界面名称不赋予 Host 系统消息角色，也不改变 Worker 追问或报告提示词。启用来源摘录和专家输入填充已说明的变量。

新题包默认每题两次；新 Worker 会话缺少策略时采用该默认，新覆盖上限为两次。授权题与纯选择题不提供文本框、不调用模型。条件“其他”须同时选中并填写文字。管理员可保存 0–2 次、每题或整场计数。新访谈预览采用当前设置，刷新保留冻结访谈。失败保留答案，允许继续或以新输入修订显式重试。

本决策部分取代[发布设置](2026-10-14-worker-direct-publish-settings.zh.md)和[参与者入口](2026-10-13-worker-interview-portal.zh.md)的策略配置前提；两者仍负责认证、不可变发布与执行冻结，因此均未被完全取代。

## 考虑过的替代方案

用摘要替代正文会丢失可检查证据；每次发送所有书籍浪费上下文；种子覆盖已有文献会破坏用户编辑；刷新时重新解析配置会改变访谈；为选择题增加文本框会虚构题目没有的回答方式。

## 影响

客户端包包含约 7.7 MB 来源正文，生成文献上下文少于 42,000 字符。原文件摘要和行号定位所提供的 OCR 版本，不代表已核实书目信息；无结构迁移重写冻结访谈。实际 EXE、Edge、隔离 MySQL 和本机模型替身验收约束发布、设置持久化、条件文字和失败恢复；单元测试约束原文摘录、上下文预算与用户数据优先级。替身验证请求链路，不代表真实模型质量或麦克风已验收。

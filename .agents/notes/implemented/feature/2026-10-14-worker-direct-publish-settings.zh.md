# Agent Note：Worker 发布与执行配置冻结

Status: implemented

[English](2026-10-14-worker-direct-publish-settings.md) | 中文

## 问题

此前工作台未向 Worker 上传题包便标记已发布。运营还需要可见的每题包追问控制和可编辑业务提示词， 同时让进行中的访谈保留开始时使用的模型、提示词和预算。

## 决策

使用明确的 Worker 地址和自有弹窗。旧发布桥通过 Worker 管理会话授权一次上传，并绑定窗口、origin 和 nonce；原生桌面发布使用仅限上传的 Key 代理。管理员凭据和后端令牌不传给 DSH。[输入策略决策](2026-10-16-traceable-interview-inputs.zh.md)负责默认策略与参与者直接进入行为。

向不可变题包接口发布稳定 JSON 字节，DSH 仅凭匹配回执标记发布。取消和失败释放操作，重试沿用相同字节。新版本显式创建且不调用模型。邀请凭据留在片段中，消费片段后直接进入。

将有修订号的设置与上传题包分开存储。业务提示词按 YAML、全局默认、题包覆盖逐层解析；题包策略 覆盖发布时的初始策略。在参与者进入时保存不可变执行快照，包括两类 release、公开模型与服务配置、 队列预算和已解析策略。凭据仍在启动配置中。仅使用后端 API 的访谈在首次提交时冻结。后续任务及 报告版本均沿用快照。可编辑提示词不能改变 Go 中的 schema 或引用校验规则。

DSH 不提供题包策略表单，发布、JSON 下载和新版本由问题包操作栏承载。新发布携带当前默认输入策略，目标取自访谈标题；既有保存目标和原版本策略继续支持字节稳定重试。输入策略决策部分取代原先明确配置策略的前提，设置存储和访谈冻结仍由本记录负责。


## 考虑过的替代方案

在客户端嵌入后端令牌或管理员密码会授予过大权限。让任意浏览器 origin 借用管理会话会使非信任网站 能够发布。为修改设置重写不可变题包 JSON 会破坏重试身份和历史。每次任务都解析当前提示词会使访谈 中途改变规则。

## 影响

结构版本 3 新增配置和访谈执行快照表，不重写历史。旧访谈保留已有追问和最早报告 release；若从未 记录报告 release，首次恢复时捕获服务启动基线，不采用新的管理端覆盖。未记录过的历史模型配置无法 重建。结构版本 2 的二进制拒绝结构版本 3；部署及回退要求见 [Worker 参考](../../../../worker/README.zh.md#schema-migration-and-rollback)。

真实隔离 MySQL 和浏览器验收使用一次性数据库、受控模型端点及合成题包，覆盖认证、重试、 全局与题包继承、进程重启、执行冻结和已保存 PDF 下载。DOM composition 测试不代表原生输入法、 麦克风或真实模型已验收。

[完整 Web Loader 验收](../../../../apps/web/tests/worker-publication.e2e.ts)在一次性 profile 中挂载真实访谈插件和已安装的侧栏服务。浏览器通过实际按钮创建宿主会话，向一次性 Worker 发布，再检查回执、分享页快照、口令预填和明确点击进入。仅组件替身不能替代这条组装后的链路。测试需要显式提供已安装插件和私有 Worker 交接文件；缺少输入时，相应检查会跳过。

原生桌面验收使用隔离 profile 启动实际打包程序及真实 Worker HTTP 处理器和资源。合成账号与 SQL 存储用于隔离验证已登录单击发布、登录后继续、地址缺失提示、弹窗受阻、旧协议拒绝及网络错误，不使用生产凭据或模型调用。同时验证旧题包字节、Worker 自有设置、邀请链接复制及明确点击参与者入口；这不替代 MySQL 集成或真实模型、麦克风验收。

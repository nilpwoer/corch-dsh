# Agent Note: Worker 六位数字口令

Status: implemented

[English](2026-10-19-six-digit-worker-invitations.md) | 中文

## Problem

长口令不便手动转录。缩短口令必须保留 Worker 权威、既有访问，以及独立的管理员、发布和会话凭据。

## Decision

Worker 使用 `crypto/rand.Int` 在 000000 到 999999 中均匀抽样，再格式化为六字符字符串，保留前导零。随机源失败返回错误，不提供替代口令。显式轮换会拒绝与原口令相同的抽样，即使数字空间允许碰撞，也确保旧口令失效。口令按题包作用域校验，不要求全局唯一。

[Worker 自有口令决策](2026-10-15-worker-owned-invitations.zh.md)继续负责创建权威、不可变题包绑定、稳定重试、修订校验的管理操作及旧数据兼容。本记录仅替代其高熵格式选择，权威设计仍保持活跃。既有数据库及题包口令继续作为精确字符串处理，包括长口令；读取和重试不会缩短或重置它们。不需要数据库迁移、桌面端修改、缩短 API Key 或改变参与者 Cookie。

## Attempt limits

`POST /portal/api/session` 在解析或校验口令前消耗既有 `portal.login_window` 内的 `portal.login_limit` 预算。所有题包和客户端地址共享每个 Worker 进程中挂载处理器的一份固定窗口计数，正确和错误尝试都计数。预算耗尽返回 429 / `LOGIN_RATE_LIMIT`，即使口令正确也一样。重启或另一个进程拥有独立计数。示例配置允许每分钟 20 次，这并不代表已部署的实际设置。

仅一百万种可能，使持续在线猜测成为实质风险。每分钟 20 次不重复猜测，针对一个口令持续一天的成功概率为 2.88%。当前计数限制单进程的总流量，但没有持久化失败预算、多实例共享状态、逐题包退避或口令过期；还可能阻断无关的正常参与者。它不能证明六位秘密具备充分的长期保护。额外锁定、过期或加强验证会改变访问语义，需要运营方另行决定；此次修改既不添加这些行为，也不放宽现有限制。

## Alternatives considered

**保留长随机口令**提供更大的猜测空间，但不满足所要求的转录格式。**客户端生成或按时间派生数字**会削弱 Worker 权威或不可预测性。**随机字节直接对一百万取模**在没有拒绝抽样时会引入偏差。**自动轮换已存口令或接受数字类型 JSON**会使既有邀请失效，或丢失前导零。**静默添加锁定或过期**会超出口令格式请求，改变参与者访问和恢复行为。

## Consequences

仅新建访问和显式轮换使用六位数字。更新 Worker 二进制后该行为生效，既有桌面端和 SPA 的字符串处理保持兼容。既有长口令继续有效，直到管理员明确轮换或撤销；活跃参与者会话仍独立。源码实现不意味着已经生产部署或重置凭据。

针对性测试覆盖安全随机生成、前导零、范围拒绝、随机源失败、轮换碰撞拒绝、新旧口令精确校验、HTTP 入口及既有共享失败限制。HTTP 测试使用隔离文件和内存后端，不使用生产数据或调用模型。共享持久化猜测防护仍是明确缺口，不代表已接受生产安全性。

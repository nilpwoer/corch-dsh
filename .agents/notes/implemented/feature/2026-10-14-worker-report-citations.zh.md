# Agent Note: 保存检查点前校验报告引用

Status: implemented

[English](2026-10-14-worker-report-citations.md) | 中文

## Problem

模型响应即使符合基本 JSON 结构，也可能遗漏引用、引用未知证据，或把未确认的背景资料写成访谈事实。业务校验前保存该响应，会使重试复用同一个无效结果。

## Decision

报告证据提取和编写采用带版本的检查点名称，只有同时通过结构和业务校验才能保存。模型获得本次允许引用的证据 ID、条件引用要求，以及区分回答与未确认背景的指令。证据原文必须匹配已保存的回答。证据为空时，只允许 `needs_verification` 陈述，任务卡必须为空。

`prompts.report.max_corrections` 将每阶段零至三次额外调用的预算冻结在报告发布版本中。被拒响应保留在调用审计中，下一次调用获得失败字段路径和原始输入；只有有效响应成为检查点。修改配置需要新的发布版本号。历史失败报告和检查点保持完整。

## Alternatives considered

随意挂上证据 ID 只能满足结构检查，不能支撑陈述。取消引用校验会发布无依据结论。反复复用已保存的无效响应会重复失败，因此拒绝这些方案。

## Consequences

纠错可能增加供应商调用费用，但受冻结预算和任务超时限制。未知 ID、事实或任务卡缺少引用、编造原文及无证据事实均被拒绝。这些检查确保证据来源，不能证明语义蕴含；真实报告验收仍须比较陈述与所引用的原文。模型测试覆盖拒绝、有限纠错及检查点复用，进程验收快照记录组装后的请求和响应。

# Agent Note: JD 搜索项目与工作区文件

Status: implemented

[English](2026-10-25-jd-search-project-artifacts.md) | 中文

## Problem

岗位搜索完成后需要形成可重新打开的项目记录，清洗后的岗位描述和生成的典型工作任务报告也需要保存在 DSH 工作区。

## Decision

工作台以 DSH 会话 ID 为键，将项目元数据保存在浏览器本地存储中，并从侧栏打开对应会话。浏览器存储不可用时，当前运行中的客户端保留内存索引；修改剔除选择会使旧分析和报告失效。搜索完成后，工作台重命名该会话，并调用会话的工作区文件工具，将岗位数据写入 `outputs/jd-search/<session-id>/jobs.json`。任务分析完成后，同一会话会在岗位数据旁写入 `typical-work-tasks.md` 和套用模板样式的 `typical-work-tasks.html`。工作台通过主机默认应用打开已保存的 HTML，通常是浏览器。报告包含已确认 JD 证据、动词开头且可独立交付的任务、样本频次提示和专业能力标签。频次仅描述当前样本覆盖情况，不估算整个劳动力市场。

分析提示词遵循 JD 驱动能力图谱方法：保留证据编号、合并语义相同的任务、不把泛化的配合或参与描述单独作为任务，并且只映射专业能力标签。搜索结果同时保留清洗后的 JD 正文、摘要和来源链接。

最后的“保存搜索项目”操作会重新写入两份报告；只有工作区确认两个文件都已写入后，项目索引才会增加 `finalizedAt`。后续工作台可以读取项目记录中的报告路径和时间戳。修改已确认的 JD 样本会使该标记失效。

JD 编排只在绑定会话没有运行中或排队任务时接收提示词。发送前先订阅会话，以精确提示词文本识别新的持久化用户输入，并在对应轮次的结束记录出现后读取其最终助手文本。会话转为空闲后才返回，确保后续文件请求能够准入。流式 JSON 不能提交为搜索结果。固定浏览器时限无法代表排队、工具和模型的总执行时间，因此完成状态由会话生命周期决定；失败、中止、取消和会话移除都会明确释放订阅。

浏览器项目元数据缺失时，工作台可以从会话恢复最新一次已完成的搜索。恢复要求精确的生成提示词和有效岗位数据；最新搜索未完成或失败时不使用更旧结果，也不覆盖已有项目。恢复不发送提示词，也不宣称工作区文件已经写入。因此，即使旧客户端提前停止等待，持久化会话仍保留迟到结果。

## Alternatives considered

**通过客户端文件系统 API 直接写文件：**工作台使用的客户端工作区服务提供工作区和文件导航，但没有写入操作。当前会话的 DSH 文件工具可以在工作区中写入文件，无需新增客户端 API。

**只将岗位内容保存在浏览器存储中：**这会让文件只存在于特定浏览器，无法在 DSH 工作区形成可交付文件。

**分析结束后才创建项目：**分析延迟或失败时用户会失去已完成搜索的项目入口。搜索结果返回后立即创建项目；之后的文件错误会显示在界面上，但不会删除项目记录。

**使用固定浏览器超时：** 工具和模型仍在正常执行时，有效搜索可能已超过该时限。此时取消订阅，会留下右侧已有回答、左侧却没有项目或步骤跳转的状态。本次准入任务的已记录结束状态才是结果可用的依据。

## Consequences

项目元数据遵循浏览器本地存储的生命周期，并限定于当前浏览器来源。岗位数据和报告保存在 DSH 工作区，依赖当前会话可用且文件工具成功完成写入。项目会记录文件路径，便于重新打开和排查。文件写入失败不会隐藏搜索结果或移除侧栏项目。最终冻结标记属于项目元数据，两份工作区报告是后续工作台共享的冻结交付文件。

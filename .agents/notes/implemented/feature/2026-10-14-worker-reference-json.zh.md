# Agent Note: 稳定的参考资料 JSON 标识

Status: implemented

[English](2026-10-14-worker-reference-json.md) | 中文

## Problem

MySQL JSON 存储会重排对象键。保存的题目参考资料采用原始 JSON，因此同一快照在入库后可能得到不同哈希。刷新冻结访谈后重新生成报告，可能被题包或输入版本检查拒绝；历史幂等记录也可能拒绝等价请求。

## Decision

题目 JSON 序列化递归排序参考资料对象的键，同时保留字段值、数字精度、未知字段及数组顺序。哈希与接口响应使用相同序列化方式。提示词发布版本和题包发布哈希保持原有序列化方式。

保存的请求摘要不同时，幂等检查使用规范化题目 JSON 比较完整的历史提交。相同版本的快照摘要不同时，只有完整历史快照规范化后相等才可接受。现有摘要、快照、回答和报告保持不变，新版本和新请求保存规范化摘要。

## Alternatives considered

**前端重建**只能修复单个调用方，后端重放与历史幂等仍不一致。**全局修改哈希**会影响无关的提示词发布标识。**重写数据库**需要为不可变记录协调迁移和回滚。局部序列化配合历史输入比较避免了这些代价。

## Consequences

参考资料对象键顺序变化不再影响存储、刷新和重试。回答、参考资料值、数组顺序、请求类型及版本发生变化时，仍具有不同标识。隔离 MySQL 验收覆盖历史摘要、重复请求、冻结会话重新生成以及内容变更拒绝；浏览器验收刷新真实 Portal 并使用受控模型接口重新生成报告。

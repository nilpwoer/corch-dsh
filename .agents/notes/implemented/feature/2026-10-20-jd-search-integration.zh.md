# Agent Note: 有来源依据的 JD 搜索集成

Status: implemented

[English](2026-10-20-jd-search-integration.md) | 中文

## 问题

JD 工作台需要真实公开岗位正文。仅在基础 bundle 启用抓取仍会让浏览器会话缺少该工具，因为内置 Agent 预设拥有各自的工具注册。模型还可能引用与实际抓取页面不同的岗位编号，因此看似合理的链接与摘要不能证明来源。

## 决策

标准、代码和 Cordis 预设启用 `web_fetch`，使用 Host 的 HTTP 提供者。基础 importer 补充该 workspace 依赖，保留既有包解析。JD 岗位推理和搜索只使用其所属会话；切换会话重新挂载工作台，不复用其他会话的结果。结构化输出等待完整闭合的 JSON 对象，请求终止错误直接反馈到表单。

搜索提示词要求已抓取的来源正文，禁止猜测职责、编造日期、安装软件和绕过访问控制。展示岗位前，`verifiedJdSearchJobs` 校验模型字段，并把来源链接与本次搜索开始后记录的成功 `web_fetch` 结果精确匹配。已知重定向使用最终规范链接。搜索摘要、失败抓取、历史证据和未匹配的岗位编号均不能成为结果依据。这项校验确认来源已读取，不能保证模型摘要的每个事实或岗位仍在招聘。

结果支持查看公开原始来源、剔除和恢复；空结果说明如何调整搜索。任务和能力分析使用保留的岗位。工作台明确提示搜索项目保存尚不可用；提供者会话保留普通对话记录，JD 表单和结果状态仍仅保存在内存中。本次集成不改变 Worker、发布、口令、报告、专家答题或数据库格式。

## 考虑过的替代方案

**语法校验通过后直接信任模型来源链接。** 真实搜索曾返回与成功抓取页面不同的岗位编号。精确工具证据阻止这种不匹配成为可点击的结果。

**抓取失败时使用搜索摘要。** 搜索摘要可能缺少职责和日期。返回更少的已核验岗位或空结果，可以区分来源证据与推断。

**回退到其他可用对话。** 这样可能把 JD 请求和输出写入无关访谈。所属会话缺失时明确报错。

## 影响

真实搜索与分析使用用户已配置的模型和原生搜索提供者，产生普通提供者用量。公开网站可能报错、要求登录或更改内容；工作台不能保证目标条数或岗位仍有效。搜索项目历史持久化和登录态浏览器采集流程仍待实现。验证包含真实模型、搜索与抓取执行，以及岗位推理参数、空结果/错误、来源不匹配和原有访谈/发布的针对性回归；合成回归不能替代真实搜索证据。

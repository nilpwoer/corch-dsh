# Agent Note: 浏览器优先采集 JD 与持久化平台停止

Status: implemented

[English](2026-10-23-browser-first-jd-collection.md) | 中文

## 问题

招聘页面依赖 JavaScript、平台 Cookie 与人工验证。匿名 HTTP 可能在状态码 200 时返回空应用壳或验证页。仅靠提示词不能阻止重复请求，也不能把搜索摘要变成原文。

## 决策

模型通过 `web_search` 发现链接，本次工具元数据证明候选来源。所有已存档 JD 会话都在工具执行前被限制，包括恢复的会话。明确的搜索操作开放有限搜索预算，其他工具、操作结束后的调用及超额调用均被拒绝。访谈会话沿用自己的策略。外部提供者控制其搜索爬虫，本机浏览器限速不能约束提供者服务器。

原生采集器在平台窗口中渲染已存档候选，使用持久化 Chromium 分区。公开页面无需登录，各平台分别复用浏览器存储，跨项目和重启保留。模型与外部页面没有 Cookie 接口。采集器对各平台串行导航，执行最小间隔与滚动小时预算，超出批量上限的候选保留待采。成功原文使用校验哈希、设有有效期的缓存，并保留最初采集时间；复用不会伪造新的采集时间。

HTTP 429、验证路径和可识别的渲染安全验证页会持久化停止该平台。停止期间拒绝主框架导航、跳转、弹窗与后台请求，重启后继续生效。需要登录的页面暂停该平台自动采集，不冒充安全验证。明确的人工验证操作临时开放平台窗口；恢复只检查当前页面，不发起导航，取得有效 JD 后才解除停止。平台停止时仍可离线读取有效缓存。设置与私有数据位置见[桌面指南](../../../../apps/desktop/README.zh.md)。

明确要求登录后查看完整内容的原文不能进入新图谱语料，即使公开片段中存在真实引文。既有项目和图谱版本仍可读取且保持不变，拒绝新用途不会改写历史证据。

[来源证据决策](2026-10-20-jd-search-integration.zh.md)继续约束原文归属、逐字引文与推断标记；[已确认工作台决策](2026-10-23-confirmed-jd-workspaces.zh.md)继续约束独立存档、不可变确认及 HTML 报告。

## 考虑过的替代方案

**先匿名抓取，失败再开浏览器。** 状态码 200 的应用壳不是 JD，在渲染前请求它增加访问量而没有取得证据。**仅用提示词限制。** 模型仍可能请求其他 URL、Shell 或反复搜索，Host 须在执行前拒绝。**跨平台共用一次登录。** 独立网站各自控制账号和 Cookie 域名；复用各站会话可减少重复登录，不能声称跨站认证。**等待后自动重试验证页。** 这可能延长限制，恢复须有明确人工操作和可读取的原文。

## 影响

持久化浏览器存储减少重复登录，但仍可能过期或被网站拒绝。内嵌浏览器不兼容、岗位失效、网络错误及强制登录仍可能阻止采集，采集器分别记录结果并保留候选。真实平台验收记录实际结果与导航证据，不连接远程调试、不绕过访问控制；原生及桌面装配合成测试证明策略、缓存、重启、工具拦截和证据持久化行为，不证明所有平台可访问。

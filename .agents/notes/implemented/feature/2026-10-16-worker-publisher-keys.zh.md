# Agent Note: Worker 发布 API Key

Status: implemented

[English](2026-10-16-worker-publisher-keys.md) | 中文

## Problem

客户端发布依赖管理员会话时，首次使用或过期会中断上传并要求登录。共享管理员身份也扩大了客户端所需权限。主持人要求保存专用Key后一次点击发布，并保持参与者口令与旧题包兼容。

## Decision

Worker管理员创建命名、可撤销且可选到期的上传Key；明文只在创建时返回，MySQL保留哈希。独立上传接口仅返回本次不可变发布回执，不能用于报告、管理或模型API。系统加密的桌面保管区通过窄IPC配置，只向本地主窗口提供非敏感状态和发布操作；远端访谈窗口无预加载接口。传输不跟随重定向，分享URL经过同源与参与者路径校验。浏览器不保存发布Key。

界面以当前版本成功回执显示已发布，校阅后只需一次发布操作。高级提示词默认折叠，报告、设置与Key管理分页。参与者口令规则继续由[既有决策](2026-10-15-worker-owned-invitations.zh.md)拥有，旧浏览器桥接继续可用，新桌面流程不依赖它。

## Alternatives considered

**复用管理员Cookie。** 无法保证首次配置后直接发布，并给客户端超出上传所需的管理员身份。

**静态配置令牌。** 创建与撤销需要修改服务器凭据并重启，无法由既有管理端按名称管理。

**浏览器持久化Key。** 普通网页脚本与本地浏览器存储会获得长期明文；原生系统加密保管限制该暴露。

## Consequences

结构5新增空Key表，旧结构4程序拒绝读取。所有新写入前可经停止写入者与完整指纹检查恢复结构3/4；Key创建、使用、撤销或业务变化后必须保留5并兼容修复。撤销不终止已授权的在途请求，遗失Key只能撤销重建。Windows用户变更后需要重新保存Key，纯浏览器不能直接发布。

## Verification

HTTP与原生测试覆盖首次无Cookie上传、权限负向检查、哈希与一次显示、到期/撤销、稳定重试、取消和重复合并。独立MySQL验收验证迁移、恢复与旧数据。实际EXE及浏览器验收覆盖配置保存重载、单击进入、错误引导与页面分离。真实模型、麦克风和生产部署不由这些合成验收证明。

# Windows 版 Corch DSH 桌面客户端

[English](README.md) | 中文

桌面启动直接从随包运行库解析内置插件，不在 `data` 中创建符号链接或目录联接，不需要管理员权限或 Windows 开发者模式。替换程序时保留原有 `data` 文件夹，即使此前启动失败也不应删除它。已有配置清单、补丁、凭据、会话和额外插件目录会保留。


本地工作台的复制按钮可以向剪贴板写入链接和访谈口令，网页不会获得剪贴板读取权限。


## 使用便携客户端

需要 Windows10/11 x64。把 ZIP 完整解压到可写目录，双击 **Corch DSH.exe**。包内包含 Node.js、Electron、Web 界面、专家访谈插件和已打补丁的 better-sidebar 提供器；启动时不安装系统组件，也不通过 pnpm 下载依赖。

客户端在可执行文件旁创建独立 `data` 目录，保存 Electron 浏览器配置、DSH 设置和凭据、会话、工作目录及日志。替换程序时保留这个目录。目录内含私人数据，请勿随故障报告上传。不要让多个副本同时使用同一数据目录。`Corch DSH.exe --data-dir C:\absolute\private-folder` 可指定独立配置目录；不要指向现有浏览器目录或 DSH_HOME。

在模型设置中通过现有模型与凭据服务配置生成问题包使用的模型。访谈设置另行配置 Worker 地址及其管理端创建的发布 API Key；已部署服务地址为 `https://114.132.201.209`。原生进程使用当前 Windows 账户的系统加密保存 Key，只向固定上传接口发送 Authorization 请求头；不向远端页面提供读取 Key 的接口，不使用浏览器持久化、URL、分享链接或日志保存 Key。点击「发布并打开 SPA」立即上传并打开访谈，无需额外确认或管理员登录。授权缺失、过期或撤销时，行内错误提供设置入口。Worker 与 HTTPS 反代都必须支持 `/publish/api/`。

关闭客户端会停止它自己的本机后端，不影响其他 DSH 安装或服务。HTTP 只监听 `127.0.0.1`，首次启动由系统分配端口，随后保留端口以维持浏览器存储。若其他程序占用该端口，客户端会记录启动失败，不接管或关闭该程序。启动日志位于 `data/backend.log`；启动失败会写入 `data/startup-error.txt`。麦克风授权需要原生确认；真实硬件和模型质量仍需单独验收。

应用未签名，没有自动更新功能。Windows 可能显示未知发布者或 SmartScreen 提示。包内保留 Electron 和 Node 上游许可。请从维护者取得完整更新包，并在解压前核对公布的 SHA256。

## JD 研究采集

JD 候选来源在隔离、持久化的浏览器会话中渲染，同一平台共用一个窗口。主窗口与弹窗默认内容区为 1360×860，最小内容宽度为 1280。公开原文无需登录，各平台分别复用已有登录状态，跨搜索和重启保留；网站仍可能使会话过期或要求验证，一个平台的登录不能用于其他平台。外部页面没有原生接口，Cookie 与密码不会提供给模型。迁移客户端时保留 `data/electron` 及 `data/dsh/jd-projects`，已确认 HTML 报告位于 `data/exports`。

原生采集器首次使用时写入 `data/jd-collection-settings.json`。编辑时须保留全部字段，无效设置会停止采集。`min_interval_ms` 默认 10000，约束同平台主框架导航间隔；`max_navigations_per_hour` 默认 12；`max_sources_per_batch` 默认 20，超出候选保留待后续采集；`render_settle_ms` 默认 1500；`cache_ttl_ms` 默认 86400000。已知招聘平台的子域名共用预算，其他主机分别计数。这些限制减少本机访问量，不能保证平台允许访问。

普通登录窗口被动监测 DOM 变化与导航，不发送探测请求。完整 JD 可读后，采集器记录原文 URL、采集时间与哈希，自动投递到所属搜索；目标成功后停止自动采集，不将后续无关浏览自动存档。`data/jd-collection` 内的私有投递队列可跨页面刷新和应用重启恢复，Host 保存后才确认完成；迁移客户端时应随项目数据保留。安全验证窗口即使出现可读 JD，也仍需明确确认恢复。

成功取得的渲染原文在 `data/jd-collection` 私有缓存中保留 SHA-256 和最初采集时间。有效缓存跨项目、重启复用，不发起导航；过期不会刷新采集时间。安全验证与 HTTP 429 在同目录持久化平台停止状态，覆盖后台请求和跳转；重启不清除，也不自动到期。明确的人工验证操作可打开已停止平台，恢复只读取当前页面，取得有效 JD 后才解除停止。平台停止时仍可离线使用有效原文缓存。登录页、网络错误、非 JD 页面与反爬限制分别记录。

[教学工作台](../../packages/client/ui-polus-teaching-reform/README.zh.md)说明搜索存档、来源证据、推断标记及已确认 HTML 导出。[按需真实平台验收程序](jd-platforms.acceptance.mjs)使用生产采集器且不连接远程调试，记录状态、导航时间和来源哈希。[自动保存真实验收](jd-login-live.acceptance.mjs)启动普通桌面，验证无需点击继续的 Host 存档，不连接远程调试、不发送模型请求。合成验收不能证明真实网站兼容性。

## 构建参考

桌面装配与教学插件是私有工作区包，通过便携客户端分发，不加入上游 npm 发布序列。使用 Windows x64、受支持的 Node.js、pnpm11.7.0 和 Windows PowerShell/tar。先运行仓库正常构建，再执行：

```powershell
pnpm --filter @polus-ai/corch-dsh-desktop run package:win --out C:\build\Corch-DSH
```

输出目录必须不存在。打包器核验固定版本的官方 Electron44.7.2 和 Node24.18.0 压缩包，在仓库 `.tmp` 下、发布目录之外的仅含发布文件工作区镜像中按冻结 pnpm 锁文件安装生产依赖，再将工作区包物化到便携闭包，拒绝包内符号链接及私人配置，产出 ZIP、SHA256 和逐文件构建清单。包内排除包管理器生成的启动脚本和安装元数据，避免携带构建机路径。便携包也排除源码映射、编译状态和生成的调试路径注释。`--cache` 指定压缩包缓存；`--closure` 可提供已核验的冻结桌面闭包以离线组装。该选项仍检查必要构建产物并扫描载荷；维护者需保证闭包与源码、锁文件匹配。

`node --test apps/desktop/policy.test.mjs apps/desktop/publisher.test.mjs apps/desktop/publisher-vault.test.mjs` 检查弹窗限制、环境隔离及导航。桌面验收必须以独立数据目录启动实际打包的可执行文件，加载真实插件，检查模型设置页和隔离 Worker 发布握手，并核验后端关闭。回环提供商测试只证明请求路由和凭据连接，不代表真实模型质量或麦克风验收。

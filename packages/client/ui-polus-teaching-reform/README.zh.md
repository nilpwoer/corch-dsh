# 教学改革工作台

[English](README.md) | 中文

用户确认 JD 样本并生成典型工作任务后，工作台会在岗位数据旁写入 `typical-work-tasks.md` 和便于阅读的 `typical-work-tasks.html`。HTML 报告沿用提供的能力图谱示例样式，“阅读报告”操作会使用主机默认应用打开保存后的 HTML 文件，通常是浏览器。报告包含任务描述、样本频次提示、来源 JD 编号、专业能力标签、已确认岗位信息和来源链接。任务定义和频次解释遵循 JD 驱动能力图谱方法论：任务以动词开头，是有 JD 证据支持、可独立交付的工作活动；样本频次不代表整个劳动力市场的统计比例。

项目列表元数据存储在浏览器本地存储中。岗位数据和报告通过当前会话的文件工具写入 DSH 工作区；文件写入失败时，工作台会显示错误，侧栏中的项目记录仍会保留。

五步导航可直接打开当前项目中已有数据的步骤。重新查看已完成步骤只展示已保存的输入或结果；只有用户点击对应操作按钮时才会启动搜索或分析。

在能力标签页点击“保存搜索项目”后，工作台会重新写入两份报告；只有工作区确认两份文件都写入成功后，项目索引才会记录冻结时间。后续工作台可读取项目记录中的报告路径和冻结时间。修改纳入分析的 JD 后，冻结状态会清除。

JD 操作要求当前会话空闲，并等待本次准入输入所属的任务轮次结束。流式 JSON 仅作为临时输出；任务失败、中止或会话移除时明确报错，不接收未完成的结果。等待五分钟后，工作台显示“仍在运行”提醒并继续等待。提醒覆盖岗位推理、搜索、分析及文件保存；不会仅因耗时较长而取消结果订阅。点击“取消工作流”会终止本地等待、请求停止当前主机任务轮次，并阻止后续工作流阶段；取消请求失败时明确提示尚未确认主机任务停止。主机无响应且没有终止事件时，仍需用户取消。切换视图或临时历史读取失败不会取消已接受的任务；结果订阅会等待恢复或明确的终止事件。重新打开会话时，可从最新一次已完成且有效的搜索回答恢复缺失的侧栏项目，无需再次调用模型。已保存的项目保持优先。恢复只重建浏览器中的项目元数据和 JD 内容，不确认或重复执行工作区文件写入。

## 专家访谈

客户端插件准备专家信息和带版本的问题包，并发布到显式配置的 Worker。本地访谈资料保留在浏览器中；Worker 管理参与者会话、执行设置和报告。配置在安装 `dsh-better-sidebar` 的同时挂载本插件包。

## 发布与分享

在访谈设置中保存 Worker 地址及其管理端「发布 API Key」页面创建的 Key。本机回环地址之外必须使用 HTTPS。Windows 桌面端使用当前系统账户加密 Key；浏览器仅保存非敏感目标和授权元数据。纯浏览器客户端会提示更新桌面端，不打开登录窗口。模型提供方的凭据单独配置。

校阅当前问题后点击「发布并打开 SPA」。原生进程立即上传、校验对应回执并打开参与者页面，无需第二次确认或管理员登录。缺少、过期、撤销或无效的授权会显示中文行内错误和设置入口。重复点击合并为一次请求；失败或取消后可以重试相同的不可变内容。内容变化需要新版本，未改变内容的保存保留版本号。显示状态以当前版本的成功回执为准。

新发布内容不包含访问口令。Worker 在分享链接的片段中返回邀请口令；参与者页面消费并移除片段后直接进入。原生预览请求新访谈，刷新保留本次冻结会话。浏览器保存分享回执，绝不包含发布 Key。获得完整链接的人也获得访问口令。

问题包工具栏提供 JSON 下载和新版本操作；地址框图标复制完整分享链接并提示成功。题包默认每题最多追问两次，并携带题目输入策略：纯选择题不追问；条件“其他”须同时选中且填写文字。Worker 默认继承题包策略，管理员可保存 0–2 次、每题或整场计数的覆盖。修改仅影响新访谈，同版本上传保留独立覆盖。参见 [Worker 设置](../../../worker/README.zh.md#management-settings-and-interview-freezing)。

每道专家题均常驻显示文字框。生成、Markdown 转换、编辑与发布将控件统一为 `text`（无选项）或 `mixed`（辅助选项），仅保留实质回答选项。“其他/请补充”及“不适用/暂不适用/暂不使用”等兜底控件不作为选项，叙述与补充均在常驻文字框填写。过滤依据完整控件标签及实际变体，不删除包含这些词的业务文字。旧存储模式仍可读取；专家渲染规则也适用于已发布题包及恢复中的访谈。更新 Worker 可执行程序与 HTML/JS 资源、刷新专家页面后，旧题包直接生效，无需重新发布、安装客户端或迁移数据库。新的生成与编辑行为需要更新客户端资源。历史回答、会话和固定追问上限保持不变，包括零次限制。参见[叙述输入决策](../../../.agents/notes/implemented/bug-fix/2026-10-20-always-visible-expert-input.zh.md)。

## 模型体验

### 问题包生成

#### 模型所见

生成操作读取“专家访谈 → 访谈设置 → 系统提示词”保存的全局模板，渲染后通过当前会话的 `session.prompt` 作为用户消息提交。该字段控制问题包生成，不改变 Host 系统消息角色或 Worker 的追问、报告提示词。专家字段、补充资料及启用文献摘录替换已说明的变量，已保存模板若缺少必需的回答模式协议，渲染请求会补上该协议；已生成题包保留原内容。

#### Token 影响

客户端内置所提供的 14 份 Markdown。全文检索与预览读取真实正文；启用来源仅向生成上下文提供有预算限制的原文摘录及原文件行列定位，题包元数据保留文件摘要和摘录并随发布传递。内置文献上下文总量低于 42,000 字符。用户正文、标题与启用、归档选择优先，不被种子更新覆盖。缺少正文明确报错；OCR 书目信息未经核实，Markdown 定位不代表纸书页码。生成追加渲染后的用户消息；发布和设置不调用模型。

#### KV Cache 影响

生成追加会话历史，未改变的前缀按提供方行为继续复用。发布与设置不发送模型请求。

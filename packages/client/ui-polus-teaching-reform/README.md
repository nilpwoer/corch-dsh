# Teaching reform interview workbench

English | [中文](README.zh.md)

The client plugin prepares expert profiles and versioned question packages, then publishes to an explicitly configured Worker. Existing interview data stays in the browser; the Worker owns participant sessions, execution settings and reports. The profile mounts this bundle alongside an installed `dsh-better-sidebar` provider.

## Publish and share

In interview settings, save the Worker origin and a publishing API Key created in the Worker's **发布 API Key** management page. HTTPS is required outside loopback. The Windows desktop encrypts the Key with the current OS account; the browser retains only the non-secret target and credential metadata. A browser-only client shows a desktop-update explanation and does not open a login window. Model-provider credentials are separate.

Choose **发布并打开 SPA** after reviewing the current questions. The native process uploads immediately, validates the matching receipt and opens the participant page. No second confirmation or administrator login occurs. Missing, expired, revoked or invalid authorization produces a readable inline error and a settings shortcut. Duplicate clicks share one request; a failed or cancelled operation can retry the same immutable bytes. Changed content requires a new version. Editing unchanged content preserves the version. The displayed status follows the current version's successful receipt.

New publications omit invitation credentials. Worker returns the invitation in a fragment-only share URL. The participant page consumes and removes that fragment and enters directly. Native preview requests a new interview; refreshing retains its frozen session. Browser storage holds the receipt for sharing and never the publishing Key. Anyone receiving the complete link receives its invitation.

The question-package toolbar provides JSON download and new-version actions. The link-field icon copies the complete share URL and announces success. Publications carry a default per-question limit of two and a question input policy: pure choices never request follow-ups; conditional Other requires both the selected option and written text. Worker inherits that policy until an administrator saves a 0–2 override with per-question or interview scope. Settings affect new interviews; same-version uploads preserve separate overrides. See [Worker settings](../../../worker/README.md#management-settings-and-interview-freezing).

Question-pack JSON text fields reject objects and arrays instead of converting them into display text. Every expert question has a permanent text field. Generation, Markdown conversion, editing and publication normalize controls to `text` (no options) or `mixed` (auxiliary options), retaining only substantive answer choices. Generic Other/please-specify controls and non-applicable exit controls are omitted; the permanent text field accepts all narrative and supplements. Matching identifies whole control labels, including observed variants, rather than deleting business text containing those words. Legacy stored modes remain readable; participant rendering also applies to published packs and resumed interviews. Update the Worker executable and HTML/JS assets, then refresh the expert page to repair existing packs without republishing, client installation or database migration. Updated generation and editing require the client assets. Existing answers, sessions and pinned follow-up ceilings, including zero, remain unchanged. See the [narrative-input decision](../../../.agents/notes/implemented/bug-fix/2026-10-20-always-visible-expert-input.md).

## JD search

The JD model discovers candidate links through native `web_search`; only URLs present in this search’s tool metadata are retained. Candidates are saved before desktop browser collection and cannot establish source originals by themselves. The Host restricts every saved JD session to search tools during explicit `/jd/discovery-begin` and `/jd/discovery-end` operations; `maxDiscoveryCalls` defaults to five per operation. Anonymous `web_fetch`, Shell and other tools remain denied outside and inside discovery, including restored sessions and late model calls. Ordinary interview sessions retain their own tool policy. The external search provider controls its own crawler; desktop platform limits govern this client’s browser accesses. See the [browser-collection decision](../../../.agents/notes/implemented/feature/2026-10-23-browser-first-jd-collection.md).

Known recruitment platforms’ default-port HTTP links normalize to HTTPS without changing their host, path or query. Both search metadata and model selections use this normalization, and pending candidates are saved before collection. Unknown hosts and explicit nonstandard ports are not upgraded. The native collector records invalid links independently and continues with later candidates; original positions still count toward the batch limit. Public HTTP collection remains prohibited.

## JD research projects

Every new search immediately creates its own DSH session and Host project under `DSH_HOME/jd-projects`. The sidebar lists archived searches; switching restores draft target fields, filters, capture text, current step and selected graph version. Pending writes complete before history navigation. Repeating a completed search creates another record with copied criteria. Atomic writes, writer locks and optimistic revisions prevent overwrites. The loopback-only `/jd` channel provides list, read, save, confirm, confirmed and export. `projectDirectory` overrides the directory; `maxProjectBytes` defaults to 20 MiB. Existing format-one projects remain readable. Saved originals and graph versions are append-only; exclusion affects future generations, while older graphs retain their source corpus.

JD searches pair the structured workbench with the native editable conversation, including restored sessions. At content widths of 900 px or less, **工作台** and **对话** tabs switch panes without unmounting either or losing the input draft. **仅显示对话** opens the full native view; **返回JD工作台** restores the paired view. Other session types keep their normal interface. Saved originals and the next action precede optional controls. In the originals step, **生成图谱** generates the five-level graph from retained originals. Pending sources, manual import and help start collapsed. Platform cards state whether login may be required. Job names, parent capability names and local dates replace internal identifiers, hashes and revisions in visible labels. Original text and links remain available, and platform stops retain explicit recovery actions.

The desktop renders candidates sequentially using a shared persistent browser session. Public JD pages need no login; each platform reuses its own cookies across projects and restarts. Opening a selected source starts passive page monitoring. After ordinary login, a readable complete JD is captured and saved to the originating search without a continue action, changing the selected search or invoking the model. Login forms, partial login walls and challenge pages cannot trigger a save. Manual capture remains available. Platform state distinguishes readable pages, login requirements, cached originals and blocked access. Security challenges or HTTP 429 persistently stop automatic platform requests, redirects, popups and background access. **处理平台验证** permits an explicit human verification window; recovery reads the current page and clears the stop only after obtaining a valid JD. A readable page after security verification still requires explicit recovery confirmation; automatic login capture cannot clear a platform stop. It does not navigate or retry automatically. Login cannot guarantee access. Platform limits, cache settings and data locations are documented in the [desktop guide](../../../apps/desktop/README.md). An ordinary browser retains candidates without silently falling back to HTTP. Authorized text can be pasted or imported as `.txt`/`.md` with its source URL and explicit manual provenance; file selection supports keyboard activation, same-file reselection and a filename preview, with a 1 MB limit.

Automatic results remain in a private native delivery queue until the Host saves their project. The application drains that queue independently of the open workbench, including after renderer reload or restart. It shares the project writer with draft autosave, preserves the owning session and acknowledges only a successful save. Repeated delivery is idempotent; failed saves remain pending for retry. Successful sources are delivered during a batch and reported after their Host save, including while other candidates are still loading. Platform counts reflect this search’s saved browser originals rather than inferred account login. An expired source retains its reason and a view-page action; automatic collection skips it until the user chooses another source.

Sources retain their URL, acquisition time, method and SHA-256. BOSS list details require a unique same-origin detail link matching the displayed job title, or a standalone detail page; detail URLs omit queries and fragments. Browser originals contain rendered text, not HTML bytes; truncated, login and challenge pages are rejected. Search date and region are criteria rather than verified facts about every original. Five-level graphs reject incomplete hierarchy, unsupported direct statements and quotes absent from retained originals. Quote coverage describes the frozen sample, not market prevalence. Inferred workflows, knowledge and assessment remain marked for expert review.

The single graph step first offers **确认能力图谱**. The Host records that immutable version and its confirmation time for later curriculum use; `/jd/confirmed` lists the project/version identifiers, and project read retrieves the frozen graph and originals. Confirmation is not expert endorsement. A new version needs separate confirmation. Only confirmed versions expose **导出 HTML**; the Host rejects unconfirmed exports. Reports contain a cover, contents, five-level tree, evidence table and source appendix. Frozen sources use report-local numbers and job names; citations reveal the escaped complete original offline without scripts, and the original web link remains available. Internal source, node, project and session identifiers are not displayed; hashes remain in report metadata. Numbering changes no saved evidence, graph or methodology. No model request occurs on confirmation, restoration or export. Windows saves HTML under `data/exports`, opens it in the system browser and reveals its folder if opening fails. Reports disable scripts and network resources. Browser-only export downloads the HTML and requires opening it from the downloads directory. See the [confirmed-workspace decision](../../../.agents/notes/implemented/feature/2026-10-23-confirmed-jd-workspaces.md).

Graph generation waits for the submitted instruction’s durable turn completion, then validates JSON, every five-level branch, exact quotes and direct/inferred labels. Rejected responses regenerate with the identical instruction and source corpus; no node, quote or label is silently repaired. Only a validated response becomes a new version. `maxGraphAttempts` defaults to three and accepts 1–5; exhaustion retains existing versions and confirmations. `modelIdleTimeoutMs` defaults to 300000 and bounds waiting without active generation or a usable connection. Active model turns have no fixed elapsed-time deadline. User stop, removal, request failure and plugin disposal stop the operation without another graph attempt. Per-session single-flight prevents duplicate feature generation; switching views preserves attempt status. The loopback-only `generation-policy` operation supplies these Host settings.

## Model Experience

### Question-package generation

#### What the model sees

Generation renders the saved global template from **专家访谈 → 访谈设置 → 系统提示词** and sends it as a user message through the current session’s `session.prompt`. This field controls question-package generation; it does not change the Host’s system-message role or the Worker’s follow-up/report prompts. Expert fields, supplied materials and enabled reference passages replace the documented placeholders. A stored template missing the mandatory answer-mode protocol receives that protocol in the rendered request. Existing generated packages retain their content.

#### Token effect

The fourteen supplied Markdown documents are embedded in the client. Full-text search and preview read their exact bodies. Enabled sources contribute bounded verbatim passages with original-file line/column positions; generated metadata retains source hashes and excerpts through publication. The total built-in reference context is below 42,000 characters. Existing user text, titles and enable/archive choices win over seed updates. Missing bodies fail explicitly; OCR metadata is not verified bibliography and Markdown positions do not assert printed page numbers. Generation appends this rendered user message; publication and settings make no model call.

#### KV Cache effect

Generation appends to session history, preserving reusable unchanged prefixes according to provider behavior. Publishing and settings send no model request.

### JD inference, search and analysis

#### What the model sees

Role inference receives the major and optional direction. Search receives the chosen titles, platforms, region, publication window and count limit, and returns candidate-link JSON. Search snippets remain discovery evidence and never replace original JD text. Graph generation receives retained JD originals, source identifiers and hashes. It returns project → task → process → skill → knowledge nodes, literal source quotes, direct/inferred labels and explicitly inferred assessment suggestions. These are user messages in the owning session; Worker publication credentials and private expert records are absent.

#### Token effect

Inference, search and analysis are separate model operations. Native web search incurs auxiliary provider calls and adds discovery metadata; browser collection makes no model call. Retained JD originals add context during graph generation. Validation retries repeat the original generation instruction and incur additional ordinary model usage, bounded by `maxGraphAttempts`. Graph confirmation and HTML export read saved data without model calls. The five-result test mode is an upper limit, not a guarantee. Source matching, exclusion and displaying results make no extra model call.

#### KV Cache effect

Operations append to the same owning session and can reuse its unchanged prefix. A new JD session has separate history.
